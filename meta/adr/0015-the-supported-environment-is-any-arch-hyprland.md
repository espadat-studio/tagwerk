# The supported environment is any Arch Hyprland, not Omarchy

`README.md` and the docs site both already promised that any Arch Hyprland works, while the poller read a cwd only from kitty, only over Omarchy's per-pid socket, and only when the focused window's class was literally `kitty`. That promise was untrue in a sharper way than portability: Omarchy 4's own default terminal is foot. `hyprland-xdg-terminals.list` names exactly `foot.desktop`, `omarchy-base.packages` installs foot, and kitty appears in no `*.packages` file at all, so the terminal sensor was dead on a stock install of the one platform the README claimed to be built and tested on — every terminal minute writing `cwd: null` and falling through to a title rule or `personal/other`. The machine this was written on worked only because `~/.config/xdg-terminals.list` had been switched to kitty by hand. The claim is therefore made true rather than retracted: the CLI targets any Arch Hyprland, and the bar widget alone stays Omarchy-only.

Rejected: narrowing the claim to Omarchy 4 and deleting the sentence, which costs no code and is the honest move when a promise cannot be kept — but the narrower claim was false too, because a stock Omarchy 4 desktop is exactly where the sensor did not work. Rejected: widening to any Hyprland on any distro, which reopens ADR-0004 and ADR-0005 at once — the `/usr/bin/python3 -I` shebang assumes an FHS layout and the AUR is Arch-native — to serve users who can package a single dependency-free file themselves.

Consequences: no Omarchy-only mechanism may enter the CLI, which is what rejected the shortest available fix. `omarchy-cmd-terminal-cwd` sits on PATH already doing most of this job, and shelling out to it would have been two lines; ADR-0016 records why the logic is reimplemented instead. Omarchy itself offers four switchable terminals — `omarchy-default-terminal` accepts `alacritty|foot|ghostty|kitty` — and ships a remote-control config for only one of them, so the cwd sensor cannot assume any particular terminal even inside the narrower platform. uwsm becomes a documented requirement rather than a silent assumption: both units carry `ConditionEnvironment=HYPRLAND_INSTANCE_SIGNATURE` and `WantedBy=graphical-session.target`, and a Hyprland started bare from a TTY supplies neither, so they never start and the poll sensor correctly reads dark. `tagwerk init` stops shipping one machine's roots, because the template is now a stranger's first contact with the tool rather than a personal file.
