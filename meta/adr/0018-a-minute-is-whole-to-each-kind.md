# A present minute is whole to each kind and split within one

Supersedes [ADR-0003](0003-even-split-attribution.md). That decision credited every present minute exactly once, split evenly across the repos holding a lease, so report totals equalled wall-clock presence. Agentic development broke the premise it rested on. An agent turn in one repo leases it for ten minutes whether or not the user looks at it again, so running Claude Code against a work repo and a personal repo at the same time is now the ordinary case rather than the concurrent-agent edge ADR-0003 rejected. On 2026-09-22, 69 of 90 present minutes held both a work and a personal lease. The even split halved every one of them: September's paid total read 15:34 against 27:16 of work actually attended, and `render_invoice` put 15.50 hours on a table a customer reads instead of 27.25. An hours ledger that loses eleven billable hours a month is not conservative, it is wrong in the direction that costs money.

Leases are grouped by kind. Each kind present in the group takes one whole minute, divided evenly among that kind's repos. A minute with two work repos and one personal repo leased credits each work repo a half and the personal repo a whole. The asymmetry is the point: a minute genuinely is both a work minute and a personal minute when two agents run against both, because the kinds answer to different payers and only `work` reaches the invoice (ADR-0006). It is never two billable work minutes, because those answer to one payer and one clock. The even split survives inside a kind for the same reason ADR-0003 chose it: no signal tagwerk can see says which of two concurrent agent turns in the same territory deserved more of the minute, and inventing a weight would be inventing a number.

Rejected: crediting every lease a whole minute, which is what the problem suggests on first reading and what makes the work total correct. It also bills the same payer twice whenever two work repos overlap, which is the failure ADR-0003 existed to prevent, and it is not a hypothetical -- 2026-09-21 renders 25:36 in a single day under that rule, more hours than a day has. Rejected: shortening `beat_lease_min` from ten so fewer leases overlap. It is a config edit rather than a code change and it does reduce phantom parallelism, but it treats a measurement artefact as if it were the model and still under-credits the parallel work that is real. Rejected: weighting a split by beat count, which would let a chatty agent outbid a quiet one and reads the tool's own throttle (`beat_throttle_sec`) as a measure of effort.

Consequences: report totals no longer equal presence and can exceed twenty-four hours in a day, bounded by the three credited kinds rather than by the clock. `day --json` therefore carries `present_minutes` from a dedicated walk of the idle and poll events, because `total_minutes` no longer answers the question the bar widget asks; a consumer that read `total_minutes` as presence now reads the wrong number and must be changed. The day cap measures that total and so trips more often (ADR-0011), and the week cap measures paid minutes that roughly double; caps change colours, never numbers. The fold in ADR-0010 is unaffected: a rename never changes a kind, so a retired name and its current one always share one split.
