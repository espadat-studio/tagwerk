# The `PostToolUse` beat runs in the background

The Claude hook ran `tagwerk beat claude` on every tool call and waited for it to exit. Over seventeen days this machine made 33,182 tool calls and appended 637 beats, so 98.1% of the invocations did nothing but stat a throttle stamp and exit — at 145 ms each, of which 106 ms is CPython starting, for roughly 80 minutes of blocked wall clock. `beat_throttle_sec` was already doing its job; it was simply doing it on the far side of a process boundary. The `PostToolUse` entry now carries `"async": true`, a documented hook field that runs the command without waiting, and drops its `timeout`, which is not enforced for an async hook. `SessionStart`, `UserPromptSubmit` and `Stop` fire once a session or once a turn, about 2,200 times against 33,182, so they stay synchronous and keep returning an exit code.

Rejected: `setsid tagwerk beat claude >/dev/null 2>&1 &`, drafted before the field was known to exist, which leans on undocumented behaviour about whether the parent waits for process exit or for stdout to close, turns a readable config line into a shell incantation, and discards the exit code just as completely. Rejected: `asyncRewake`, which backgrounds the hook and still wakes the model on exit 2 with the hook's stderr, but a time tracker that interrupts the session it is measuring has its priorities inverted, and it would need `cmd_beat` to exit 2 on purpose to fire at all. Rejected: a throttle check ahead of the interpreter, a shell or C shim that stats the stamp and only execs Python once the throttle has expired, which keeps the exit code and still removes 98% of the cost, but adds a second executable to a zero-dependency single file to guard against a failure ADR-0013 already catches.

Consequences: a failing beat on `PostToolUse` is now silent, which is only safe because ADR-0013 gives each agent its own darkness row and ADR-0014 bounds how long that silence can last. Every process-spawn path in Claude Code closes the child's stdin, so `cmd_beat`'s read returns at once; an empty payload falls through to `os.getcwd()`, which is the directory the handler runs in and the same value the payload carries. `--cwd "${CLAUDE_PROJECT_DIR}"` was rejected for that fallback: the variable names the directory the session started in, so a session that later moves into a worktree or a subdirectory would book every remaining beat to the original, and `~/code` is itself a root here, resolving to `personal/other` instead of a repo. Re-running the jq install line over settings that already hold an older copy of the fragment appends the async entry beside the blocking one rather than replacing it, because `unique` compares whole objects, so the old `PostToolUse` entry has to be deleted by hand.
