# Each sensor sets its own darkness threshold

`sensor_dark_h` was one week for every sensor, chosen when the beat row could not go dark honestly anyway. ADR-0013 fixed that, which promotes the threshold from a formality to the thing that decides whether a dead agent hook is caught in time. Measured against seven days of this machine's ledger, the most recent beat was at worst 8.7 h stale for `claude` and 8.8 h for `pi` at any poll, with p99 at 3.3 h and 8.7 h — an evening, not a week. A week is nineteen times the worst gap observed, and beat minutes reach an invoice, so a week of silence loses a month's agent attribution before `doctor` says a word. `beat_dark_h` is 48, and `poll_dark_h` and `idle_dark_h` stay at 168.

Rejected: shortening the one threshold for every sensor, which keeps a single key and a single sentence, but the poller and the idle listener measure whether a desktop was on, where a week of silence is a holiday far more often than a fault, and reddening those rows teaches you to read past the block. Rejected: 24 h for beats, which catches a dead hook in a day and is still three times the worst observed gap, but leaves no room for a weekend spent browsing without opening an agent — the sample is seven days holding one weekend, which is not enough to price that risk.

Consequences: `sensor_dark_h` is removed rather than kept as a fallback, so a config that still sets it is silently ignored and every sensor reverts to its own default; the key only ever appeared in the `tagwerk init` template, and nothing reads it now. `Sensor` carries its own `dark_after`, so `verdict` no longer takes a threshold from the config and a future sensor declares its own. The 48 h figure rests on seven days from one machine: a week of at-home use without agents will read the beat rows dark, and the answer then is to raise `beat_dark_h`, not to have widened it in advance.
