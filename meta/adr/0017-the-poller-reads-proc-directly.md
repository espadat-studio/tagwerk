# The poller reads `/proc` directly

Every other sensor input in this file arrives through `subprocess.run`: `hyprctl activewindow -j` for the window, `kitten @ ls` for the kitty cwd. The obvious way to descend a process tree matches that idiom — `pgrep -P` for the children and `readlink` for the links — and it would need no new test seam, because `fake_bin` already shadows a binary on `PATH` with a reply queue and every focus test uses it. The poller reads `/proc` directly instead. ADR-0012 removed a 145 ms blocking spawn, of which 106 ms was CPython starting, because it fired 33,182 times in seventeen days; the focus poller wakes every `poll_sec` seconds, which is 5,760 times a day at the default of 15, and adding two spawns per wake to the same file a fortnight later argues against a decision this repo has just paid for. Reading `children` and two symlinks costs no process at all.

Rejected: `pgrep -P` plus `readlink` on `PATH`, which is the house idiom, needs no seam and tests identically to `hyprctl` and `kitten` — but buys that consistency with 11,520 processes a day to read three files. Rejected: faking `pgrep` on `PATH` while calling `os.readlink` on the real `/proc`, which halves the spawn cost and keeps the child lookup testable, but leaves the cwd resolution itself — the part that decides which repo is billed — covered by no test at all.

Consequences: `PROC` and `SHELLS` are module constants so that tests can point them at a `tmp_path` tree, which is the one seam in this file that exists for the tests rather than for the program; `monkeypatch.setattr` is how the suite already reaches them, and `data_dir` has always been a `tmp_path` root, so the shape is not new. `fake_bin` now redirects `PROC` for every test that uses it, which matters more than it looks: before that, a focus test would have read the real `/proc` for the fixture's pid 4242, and passed or failed depending on whether that pid existed on the machine running the suite. `login_shells` re-reads `/etc/shells` on every poll rather than caching it, which is one small file per wake and keeps a newly installed shell working without a restart of the unit.
